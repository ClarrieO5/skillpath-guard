## Description

`skills/gdpr-compliant/SKILL.md` points to two reference files that cannot be opened on Linux:

- Lines 15, 156 and 194 link to `references/security.md`, but the file is named `references/Security.md`. macOS and Windows ignore letter case, so this works there. On Linux, in most CI runners and in containers, the file is not found.
- Line 16 links to `references/operations.md`, which does not exist on any OS. Its topics (cloud, CI/CD, incident response, architecture patterns) are already covered in `Security.md`, whose title is "GDPR Reference — Security, Operations & …".

This PR:
1. Renames `references/Security.md` to `references/security.md`. That matches the three existing links and the repo's lowercase-filename convention.
2. Merges the `operations.md` bullet into the `security.md` bullet, so every listed file exists.
3. Includes the matching `docs/README.skills.md` line, as generated by `npm start`.

No reference content is changed.

**How it was found and checked:** found with [SkillPath Guard](https://github.com/ClarrieO5/skillpath-guard), an offline link checker for skills. Before this change it reports 3 `CASE_MISMATCH` and 1 `MISSING_REFERENCE` for this skill; after, it reports 0. `npm run skill:validate` passes (460 skills) both before and after this change; it does not check link targets or letter case, which is why this wasn't caught. `npm start` makes no further changes.

**AI disclosure:** this change was found and prepared with an AI coding assistant (Claude Code). I reviewed the diff before submitting.
